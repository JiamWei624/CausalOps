# 0.6.0：编排、运行证据和方法检索

## 本轮完成

1. 问答与明确选定的运行绑定，并保存选择；跨运行比较单独选择同一任务的记录。
2. 建立AnalysisTools、MethodSpec和ToolResult，统一方法模式、执行分派和运行证据的归属/哈希检查；保留三类原引擎。
3. 建立SQLite检查点、执行令牌、所属进程创建标识、心跳、限次尝试和协作式取消。恢复前确认原进程已退出，先查找成功运行；不盲目重算。
4. 建立版本化研究上下文及受控观察循环：inspect_run、search_methods、ask_fact、propose_revision、finish。候选从未自动批准或执行。
5. 方法RAG加入章节定位、摘要/来源指纹、核对范围、版本和来源校验。报告保留回答当时的引用快照。

## 操作

- 在主入口创建或恢复任务。结果区上方的“当前讨论与展示的运行”同时控制结果页和本轮问答依据。
- 查看旧运行时，历史回答仍标注原运行；继续提问不会换回最近完成的计划。
- 需要比较时，勾选“本轮明确比较多条运行”，选二至三条记录。比较讨论不会追加到单运行报告。
- 在“结果与报告”下方点击“复核本次运行并提出下一步”。本地模式检索方法并列出核对事项；官方模型可在有界预算内选择只读观察。
- 只有明确勾选“允许提出新的待审计划”才可保存后续候选。候选仍要在研究计划页接受、核对事实并授权执行。
- 如果运行意外中断，点击“检查中断并恢复记录”。原进程仍在运行或身份不明时不接管；可关闭原服务后重启，再恢复。
- 取消在步骤间生效；正在运行的上游统计函数会先完成并保存结果。已取消步骤的恢复需要明确点击，不继承模型建议。

## 可用于简历的能力描述

设计并实现基于运行证据的因果分析工作台，整合结构化计划、人工审核、统计执行、报告与持续问答；使用统一方法注册表与结果契约管理探索、实验和准实验方法，建立SQLite检查点、进程身份核验和执行结果调和机制；通过章节级方法检索、来源快照及运行级引用校验约束模型解释。

这里描述已实现的软件能力。不能据此宣称可全自动发现因果、支持任意数据、具备通用代码执行能力，或已经取得真实用户效率提升。

## 验证与复现

`pytest tests/test_orchestration_v060.py`包含运行隔离、跨任务拒绝、结果契约篡改、执行令牌、取消/恢复、真实子进程提交后退出、限次修复、模型越权动作拒绝、RAG来源/段落/版本校验。

`scripts/verify_orchestration_browser.cjs`检验实际页面导入、执行、切换旧运行、刷新恢复、问答、报告下载、结果复核和显式比较。使用固定合成数据，无需真实研究数据。

`scripts/evaluate_orchestration_rag.py`对照固定开发集上的原检索与章节检索。它不是独立用户测试，得分不能视作开放问题准确率。

`scripts/evaluate_orchestration_online.py`需环境变量CAUSALOPS_EVAL_KEY和CAUSALOPS_EVALUATION_OUT；只使用固定合成表字段与汇总，不包含密钥常量。输出请求ID、tokens和结果校验状态；不测量真人时间收益。

## 保留的限制

- 本机单用户；没有多租户认证、生产任务队列或任意Python执行。
- 统计核验不能从表格证明随机化、无混杂、排除限制或平行趋势。
- 恢复是本地结果调和，不宣称跨系统严格exactly-once；原进程身份不明时不自动重算。
- 应用级模型调用预算包括语义修复；底层SDK的网络重试和超时仍由客户端配置控制。预算不硬中断在途请求。
- RAG是经整理方法摘要的章节稀疏检索；没有全文向量化、自动摄入任意论文或已验证的语义检索收益。
- 独立用户验收按当前安排留到后续。不得将测试通过率、合成数据效应或个别API调用延迟写成平台真实增长或人工效率提升。
