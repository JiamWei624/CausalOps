# LangGraph迁移实施方案（建议，未接入正式流程）

## 目标与分工

目标是把现有自建编排迁移成可以展示、暂停、恢复和逐步解释的研究工作流，保留已验证领域逻辑。主编排采用LangGraph；LangChain用于文档、检索器和工具接口；多模型网关、批准与统计合同保留。先保留Streamlit，不同时重写React/FastAPI、引入Redis/Celery或部署多租户系统。

本文是可审阅实施基线，不是已运行的代码。依赖版本须在E盘独立迁移环境进行解析、测试与锁定；不直接修改当前稳定环境。

## 阶段一：应用服务与界面分离

建议新增 `application/research_service.py` 作为界面统一入口，提供登记任务、提出计划、查看/接受候选、登记事实、批准、执行、读取运行、问答及导出等明确操作。第一阶段仅委托现有AssistantWorkspace；数据库表、运行编号和文件布局不改。

界面拆出模型配置、任务时间线、候选审核、结果证据和来源展示组件。先统一状态词：准备中、检索中、待补充、待审核、执行中、已完成、已取消、失败可恢复。解释短句说明本次阶段与下一步，而不是展示内部JSON作为主要交互。

验收：同一合成任务在新入口与原入口产生等价方法配置、数据指纹与数值结果；旧报告和历史问答仍能读取。服务入口无Streamlit依赖。

## 阶段二：LangGraph主图

建议目录：

```text
src/causalops/
  application/           # 统一研究服务与事件出口（新增）
  orchestration/         # LangGraph状态、图、节点、检查点适配（新增）
  integrations/          # LangChain检索/工具适配（新增）
  ui/components/         # 拆出的展示组件（新增）
  assistant/             # 既有任务、合同、执行运行时与上下文
  general/ advanced/    # 保留三类统计执行器
  llm/                   # 保留模型网关与授权
  knowledge/             # 保留来源登记；逐步增加业务资料与索引
  protocols/             # 保留MCP/A2A边界
```

目录是建议目标，不伪装为当前已存在结构。

建议图节点及合同：

| 节点 | 输入 | 输出 | 主要限制 |
|---|---|---|---|
| load_context | task_id、dataset_ref、selected_run | 版本化上下文引用 | 核对任务与数据归属 |
| route_intent | 问题、当前阶段 | profile/plan/answer/method等意图 | JSON校验；不授予执行权限 |
| retrieve_context | 意图、方法候选、权限 | 已定位的来源与口径引用 | 不足依据时明确返回 |
| draft_plan | 元数据、方法依据、问题 | 待审Plan引用 | 不修改人工事实 |
| validate_design | 候选、数据目录、已登记事实 | blocker与最少澄清项 | 不把声明当诊断通过 |
| await_review | plan_id、plan_sha、dataset_sha | 经核验的领域批准引用 | interrupt中断；不能由模型批准 |
| execute_plan | plan_ref、approval_ref | ToolResult引用 | 委托TaskRuntime调和与执行 |
| diagnose_results | 具体run_ref | 诊断与解释上限 | 失败时不自动挑显著方法 |
| compose_report | 事实目录、来源、指标定义 | 图文报告引用 | 数字来自事实，来源须可查 |
| answer_followup | 当前run_ref、问题 | 引用校验后的解释 | 新估计走新计划 |

路由并非每轮都遍历所有节点。方法咨询直接检索与回答；已完成运行的结果追问直接取证；只有新统计设计才进入计划、审核与执行路径。

建议状态字段：`task_id`、`dataset_ref`、`plan_ref`、`approval_ref`、`selected_run_ref`、`retrieval_refs`、`pending_questions`、`message_cursor`、`budget`、`error_summary`。图状态不放密钥、原始DataFrame、完整论文或全部历史对话。大文件保留本地引用，节点按权限加载。

## 阶段三：检查点与领域事实分别负责什么

- LangGraph检查点记录图执行位置与有限状态，用于中断和恢复。
- 研究SQLite记录数据、计划版本、批准、执行尝试、运行及证据，是领域事实来源。
- 统计节点只传引用并调用现有TaskRuntime；先按输入摘要查已有结果，再决定执行，不能给每个统计节点独立添加通用重试。
- `thread_id` 绑定任务与工作流实例，不直接把任意用户输入作为工作区路径；跨任务状态不得串用。
- 恢复时用批准ID查询领域库，核对plan_sha、dataset_sha和状态；`Command(resume=...)`带来的值不是新的可信研究事实。
- 旧计划修改、数据变化或执行器输入摘要变化，均使旧批准不适用。
- 图数据库与领域数据库分开事务，不能声称天然原子或exactly-once。采用准备记录、幂等引用和已有结果调和；进程身份不明时保持停止。

LangGraph中断恢复可能从所在节点开头重新进入，因此审核节点中不要在interrupt前执行统计、写批准或其他不可重复副作用。[官方中断说明](https://docs.langchain.com/oss/python/langgraph/interrupts)。本地开发可选择持久SQLite检查点，不能把内存Saver包装为重启后可恢复。[持久化文档](https://docs.langchain.com/oss/python/langgraph/persistence)。

验收：批准前零统计执行；拒绝后零统计执行；恢复不重复写入同一运行；旧批准拒绝；进程在已保存结果后退出可调和；丢失连接与真正进程退出区别处理；取消不破坏已完成结果。

## 阶段四：LangChain检索与工具接口

先将MethodLibrary包装为文档与检索器接口。Document元数据保留 source_id、card_id、section、locator、checked_on、access_scope、knowledge_sha256 与摘要指纹。原检索结果应能与包装后的结果逐条比对，不因换接口而丢出处。

统计工具可包装为受控工具对象，但执行入口仍要求完整领域批准引用；不能直接把任意配置暴露为无审核tool call。原StructuredModelClient可以继续供LangGraph节点调用，必要时再增加LangChain模型适配，保留接收配置授权、输出Schema校验和调用预算。

建议新增业务资料接口DataContract：字段含义、单位、观测单位、统计窗口、处理分配、数据来源与测量时点。它可以减少反复提问，但必须区分“上传者声明”和“程序检查”。

全文资料仅在合法可访问、许可与核对范围明确时纳入；章节切分保留公式、表头与上下文。业务资料与方法文献分别检索，运行数值始终使用结构化证据目录。

检索评测包括方法命中、关键限制召回、引用定位、拒答、跨任务资料隔离、同义提问，以及图表或公式语义未覆盖时的说明。当前开发回归集用于对照，不冒充独立测试集。Embedding与重排只在实际对照有改善时纳入默认，不先堆向量数据库。

## 阶段五：流式事件与交互

界面消费结构化事件，如 `context_ready`、`retrieval_completed`、`plan_ready`、`review_required`、`execution_started`、`diagnostics_ready`、`report_ready`、`failed`、`cancelled`。这些是拟议的本项目应用事件名，不是声称LangGraph已有同名内置事件。

基于LangGraph实际流接口适配这些事件，并锁定已验收版本。官方当前同时说明事件流与传统stream modes，迁移时选择一种并写合同测试。[流式文档](https://docs.langchain.com/oss/python/langgraph/streaming)。界面展示完成的动作、引用与下一步，不展示或索取模型隐藏思维过程。

输入框支持“解释一下”“按用户分组比较”“为什么没用DID”等自然提问；系统在当前运行与计划范围内解释意图。只有明确新研究或结果无法支持时，提出新的待审步骤。失败提示区分连接、格式、缺失事实、方法不适用、诊断不支持，给出实际可执行的下一步。

验收：方法咨询不产生统计运行；纯结果问答不重新估计；新计划经过批准后才执行；刷新后进度与当前运行一致；失败提示有具体原因；并发点击不重复发起同一任务。

## 阶段六：MCP/A2A与发布

保留MCP五项只读工具和A2A规则审阅。内部统计调用先使用直接领域服务，避免把本地函数全部经HTTP绕一遍。若以后接入外部MCP资料源，加入服务白名单、超时、结构检查、资料不可信标记、调用预算和单独外发授权，不让资料中的指令控制审批。

A2A以后可接独立方法审阅Agent，但必须有独立检查表、明确输入输出与验收；同一模型换角色不自动等于独立验证。当前A2A无多租户鉴权与持久任务队列，不能直接当作公网企业服务。

建议以新任务启用新编排，旧任务继续原路径；领域数据按既有版本读取。不自动迁移正在执行或待审的旧图状态。新增开关用于显式回滚，撤回新编排时保留已完成研究记录。

发布准入：原401项回归继续通过；新增图路由、中断/恢复、重放去重、外发授权与引用归属测试；至少三条端到端路线：陌生表描述性分析、已知随机实验、观察性数据识别条件不足。再做真实浏览器与独立安装验证。方法变更需额外数值参照，不用“能跑完”代替统计正确。

## 依赖与资源安排

依赖、缓存、迁移环境、向量或索引、图数据库、截图与报告全部放E盘；不在当前稳定环境直接pip upgrade。首轮只增加真正需要的LangGraph及对应持久检查点、LangChain核心接口与选定组件。最新官方文档可能与旧教程不同，安装时核对Python兼容性、依赖解析与SDK接口，生成版本与哈希锁。云端追踪默认关闭，不擅自把研究内容发到LangSmith或第三方监控。

## 下一轮最小可验收交付

“同一任务输入问题 → 自动检索 → 待审计划 → interrupt审核 → 本地执行 → 图文结论 → 运行问答”，接入真实LangGraph、保留原领域检查，附图可视化、节点事件和恢复测试。实现并验收后才在简历中写“基于LangGraph”；当前版本仍应写“自建状态编排”。
