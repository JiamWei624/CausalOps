## 五、整合与冻结判断

A **可以作为阶段候选**。以上版本能独立安装、启动，公开数据案例可复现。候选标识使用本地注释标签 stage-2026-11-05-rc1，不更改 Python 包版本。

B **本轮没有确认必须在合并前修复的 P0**。结论限定于检查过的路径；P1 会改变非预期的待审状态或遗漏答案，对复杂任务的使用者有实际影响。

C **建议进入带已知限制的 Git 整合审查，暂不作为正式稳定版本发行**。当 main 仍是核对的提交时具备快进条件。经所有者批准后，先同步并复查 main，再检查候选标签所指树、Git 历史、图片和差异清单。保留 src、tests、评测输入与评分代码、受许可示例及脱敏摘要；排除工作区、数据库、模型原文、浏览器配置、各次临时下载及缓存。复查许可、构建干净 wheel 和附带 README，再选择快进整合；main 如有新提交，在单独整合分支解决差异后重复验收。合并后至少运行全套 pytest、营销案例和 B05/B06 浏览器长流程、选定运行只读引用、模型外发权限与失败路径。此次不执行这些 Git 合并或发布操作。

D **可以进入 Eval V2.2**。将此标签作为对照，新分支单独记录用户导航、有效点击、首份报告耗时、中断恢复和主动求助；评测要求记录失败和停止原因。V2.3 再扩展到 50 题及多角色模拟。真人验证另设任务与记录；模拟任务结果不可换算为人工节省工时。
