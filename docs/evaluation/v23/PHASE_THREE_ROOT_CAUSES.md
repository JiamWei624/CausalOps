# 第三期：修复前证据与范围

基线：a23b54d；独立分支 fix/v23-research-delivery。第二期 30 题 × 两种模式的原始记录保留，评分规则继续使用 v23.2.1。不读取或运行保留集。

## 已确认根因

1. 研究语义：research_semantics.RATE 使用无边界英文子串 ratio，浓度字段等普通标识符也能命中；运行器将已登记 population 拼在用户请求前，路由随后对整段文字识别动作。metric_semantics 的每单位规则又把“的”作为比率迹象。修复分别限定英文词边界、只分离逐字匹配的已登记元数据前缀（原提交文字仍保存），并去掉单独“的”作为分母触发条件。不同字段、真实比率及中文分组分别回归。
2. 方案范围：begin 对“改按”未生成范围、reads_saved_result 未将它识别为修改；混合请求在没有日期范围时统一要求新窗口。新候选沿用显示口径却可能未继承旧 descriptive 运行的结构化日期过滤。修复登记字段别名、指标修改路径和原运行实际日期配置；禁止计划自行添加未要求的日期。对于执行器未支持的自由文本样本子集，不将 inclusion 文本当作过滤，统一在候选、批准与执行复核的语义校验入口要求澄清。分组要求必须落到 descriptive.group。
3. 答案交付：saved_answers 的极值分支返回后，检测限问题不再进入解释路径；主字段均值未稳定进入已保存事实的快捷答复。method_node 对重复记录口径主要依靠模型或通用方法材料，未保证说明“可能而非必然”。修复复用所选运行事实追加适用解释，并给出记录权重与对象等权的通用定义和反例条件。没有新增统计量或修改估计器。

## 修改边界与调用链

ResearchService.begin → 分离登记背景 / 上下文及运行绑定 → route → research_semantics.issue → LangGraph method/plan/results。
候选 Plan → plan_scope.check_steps + 已有 readiness → 人工批准 → verify_approval 复核 → 原执行器。
已有结果 → 选定运行事实 → saved_answers → 数值、单位、来源及概念边界；不创建新计算。
明确的新研究仍要求新方案与批准。已批准旧方案、历史数据和报告不改写。

## 已知限制

这是对现有校验点的有限修复：自然语言子集识别和别名读取不等于通用语义解析。未支持任意样本筛选；应明确限制并要求可验证的数据和新方案。分层平均本轮解释口径，不增加估计器。没有声称开发集改善等于独立泛化提升。
