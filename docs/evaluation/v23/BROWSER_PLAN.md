# 多角色浏览器试验准备

状态为待实施。本期未开展 V2.3 浏览器试验。角色用于改变问题背景和交付措辞；三个角色都没有数据库权限、开发者知识、正确路径或预定按钮名称。

|角色|交付目标|观察重点|
|---|---|---|
|普通业务人员|用自己的话说明业务决定、主要数值和口径；条件不足时说明要向谁补什么。|能否发现下一步、区分报告指标、理解缺数提示。|
|数据分析人员|确认分析单位、过滤与分母，完成可复核的报告或拒绝不适用的处理。|能否核对方法、来源、版本变化和运行后的证据。|
|统计研究人员|明确估计对象和识别限制，说明假设、推断单位及替代设计。|能否拒绝证据不足的结论，以及能否给出不依赖额外估计的解释。|

## 建议的 13 个场景

|主试角色|任务|目标（正式操作者只取用户题面）|
|---|---|---|
|业务|A01 岸电例会|整理含义不明确的绩效问题。|
|业务|A05 热线体验|指出现有数据能描述的范围。|
|业务|B01 协议及时率|区分两种分母，解释零进线日。|
|业务|E04 成本预测|从旧报告出发说明无法外推的金额。|
|分析|A02 科研首查|完成用户授权范围内的样本描述并找到数值。|
|分析|B02 复测权重|区分按检测记录和按标本平均。|
|分析|D02 变更样本|找到合同及审批状态，说明旧批准失效。|
|分析|E02 安全恢复|恢复到待审，再决定是否批准。|
|研究|C01 批次温度|解释观察关联的边界。|
|研究|C02 学校邀请|核对分配单位、重复测评和推断限制。|
|研究|C05 协议等效|指出等效界值及精度要求。|
|研究|E01 检测限|用所选运行解释样本极值与检测限。|
|三角色共同锚点|V2.2 N06（历史题，不计入50）|由同一订单报告出发，更换指标、审核、核对新运行、刷新并重新打开旧报告。|

共享锚点用于比较角色差异。如需估计角色影响，应对同一任务交叉分配角色并控制模型、观察内容、起点与步数；不同题组的完成率不宜直接作角色优劣比较。模拟器只收到题面、可见页面、自己的操作和普通帮助。参考答案、案例 ID 对应的正确路线、源码、数据库和服务接口不作为输入。

沿用 V2.2 的 explore、browser_actions 和 grade_explore：最多一次动作结构修复，派发前重查控件，重要动作不盲目重放。控制器另存初始状态、截图、事件、请求回执、任务墙钟、有效／无效操作、主动求助、外部介入、停止原因与终点分项。把页面已经显示的值、操作者实际识别的值、是否完成剩余操作分别记分。预置坏文件的修正版恢复只算受控恢复；停机后恢复和网络故障归类分开。

启动门槛：先封存角色说明、题面和判据，复核少量独立导航试点，不提前打开 20 题保留集。评分端有权读取本地证据，角色执行端仅可进行浏览器动作。没有真人测试时不报告真人完成率或节省时间。
