## 重跑

在本分支仓库根目录使用安装了项目依赖的 Python 3.11。输出目录需位于正式工作区之外，每批创建新目录，每题单独建库。以下路径均可替换；将 Git 加入 PATH 或设置 `CAUSALOPS_EVAL_GIT`。

```powershell
$env:PYTHONPATH=(Resolve-Path src).Path
$env:CAUSALOPS_EVAL_GIT='git'
$env:CAUSALOPS_HILLSTROM_ARCHIVE='./data/public/hillstrom.csv.gz'
$py='./.venv/Scripts/python.exe'
& $py -m causalops.evaluation.v1 --output ./artifacts/causalops-eval/pilot --cases T01 T05 T08
& $py -m causalops.evaluation.v1 --output ./artifacts/causalops-eval/baseline --timeout 120
& $py -m pytest -q tests/test_causalops_eval_v1.py
```

葡萄酒原表随仓库分发，合成数据按固定种子逐题生成。营销原始包取得方式和许可边界见[公开实验验收](../current/PHASE2_ACCEPTANCE.md)。缺少营销文件时，两题保留为“尚未测试”，不从任务分母删除。评测不读取正式工作区的模型密钥。T10 使用受控连接错误替身，全部十题都不需要网络。

## 复用现有领域记录

| 对象 | 复用位置 | 评测用途 |
|---|---|---|
| 数据、研究口径、候选方案 | ResearchService、DataContract 与 AssistantWorkspace | 通过正式入口登记和提问，保留版本及计划摘要 |
| 路由、暂停和统计节点 | LangGraph、workflow_events、SQLite 检查点 | 从持久化的开始、完成、失败时间还原节点轨迹；节点完成与统计真正成功分别判定 |
| 审批与执行 | review、verify_approval、ToolGateway 和批准回执 | 测试脚本扮演明确批准的操作者，调用同一审核服务；查询计划、数据指纹与批准时间。不得写入批准表替代审批 |
| 估计、解释和报告 | 保存运行、evidence facts、make_report | 读取结果、导出 HTML、核验文件摘要和目标运行，独立参考数值不进入问答 |
| 现有测试 | pytest、Streamlit AppTest 与既有浏览器回归 | 继续验证产品回归。本评测计时走服务层，不计入浏览器操作或真人完成时间 |

任务输入见 [cases.py](../../src/causalops/evaluation/v1/cases.py)。评分规则和数值见 [score.py](../../src/causalops/evaluation/v1/score.py)。运行器只将题目、测试操作者提供的研究口径及后续问题传入研究服务。模型和本地规划器均无评分器工具。

## 十题任务与通过条件

| 题号 | 输入和操作者动作 | 宿主评分的必要行为 / 禁止行为 |
|---|---|---|
| T01 | 红酒质量评分；要求描述分布 | 数值与保存报告一致，保留 1,599 条有效评分；不能用其他字段的统计替代。 |
| T02 | 红酒 alcohol 与 quality；要求关联分析 | 核对成对样本数和相关系数，或核对适用的单变量关联回归；结论限于样本关联。 |
| T03 | 120 条合成记录，60 个用户各重复两次；要求检查单位 | 结构审计标出 60 条重复实体记录，答复提示观测依赖；不得自动去重或假设独立。 |
| T04 | 结果 y，处理 group，post 明确在处理后测量；请求作因果调整 | 应指出这一调整不合法并拒绝据此估计，通用异常不算正确阻断。 |
| T05 | 一人一行的截面，未确认面板；请求 DID | 因缺面板或日期条件给出拒绝原因，无估计产出。 |
| T06 | Hillstrom 固定指纹压缩包；比较两周访问率 | 两组共 42,613 人，正确批准、估计、置信区间及百分点报告；不能混入第三组。 |
| T07 | 先准备待审方案，再要求方法解释 | 给出有引用的说明；已有计划集合及摘要一致，没有运行或批准。 |
| T08 | 合成 x、y、z；先批准 x 与 y 的计划，再更换为 z | 旧批准真实执行尝试被拒；新版本审批前零运行，新运行绑定 z 的方案；原方案内容不变。 |
| T09 | 先为邮件实验生成报告；再问百分点、次年净利润 | 引用当前运行并说明百分点和相对增幅；跨指标与观察期要求澄清，不得另行估计。 |
| T10 | 方法咨询；授权仅抛出连接错误的离线替身，再由操作者明确切回本地 | 确认实际发生调用及失败，未产生批准或运行；恢复后有本地来源和引用。 |

所有题统一核对运行与批准、计划和数据绑定。每项判据为布尔值，全部满足方可通过；非法设计仅在正确原因和无估计同时成立时记“正确阻断”。有部分证据但未达标记“部分完成”。违规执行、未处理异常、超时或评分无法复核记“失败”。未提供必需数据记“尚未测试”。对于自然语言解释的清晰度和建议可用性，保留“待人工复核”。

## 指标和分母

| 指标 | V1 定义 |
|---|---|
| 任务正确处理率 | 已通过与正确阻断之和 / 全部指定任务。部分完成、失败、尚未测试均不计入分子。 |
| 有效报告完成率 | 取得匹配批准的目标报告、文件哈希可复核且整题通过 / T01、T02、T06、T08、T09 中本批选定的题数。 |
| 首次尝试成功率 | 未经重试即通过或正确阻断 / 本批题数。V1 每题只运行一次，因此与正确处理率一致；开发预验收和不同提交不混算。 |
| 有效操作次数 | 日志中已登记的数据加载、问题提交、指定计划批准、候选修订、恢复动作之和。提交一个最终被阻断的问题仍是一次操作。无鼠标点击或真人效率含义。 |
| 对话轮次 | 实际提交的自然语言请求数，包括咨询、修订、追问和恢复后重新提交；审批与节点内部动作不计。 |
| 任务总耗时 | 每题子进程启动至返回或超时的实际墙钟时间；汇总为逐题用时之和，不含报告汇总与人工阅读。没有可计时动作的瞬时事件在日志中保留空耗时。 |
| 方法选择错误数 | 运行了与任务不符的估计方法，或为非法调整生成了统计结果的次数。未生成可评分输出不能据此声称方法正确；另看未通过判据。 |
| 结果解释错误数 | T09 数值与运行引用、跨范围澄清两项各记一次未通过。属于固定探针计数，不代表所有自然语言准确率。 |
| 不合法任务阻断率 | 正确阻断 / 非法设计题 T04、T05 中本批选定的题数。T03 允许完成结构检查。 |
| 故障恢复率 | 安全失败并明确切回本地后完成 / T10 故障任务数。零分母显示不适用。 |

## 如何核对结果

每批输出 `报告.md`、`results.json`、`summary.json`。每题目录包含 `events.jsonl`、`observations.json`、`score.json`、报告（如有）和独立 work 子目录。事件序号为写入顺序，节点时间戳来自领域事件。没有计划、会话或运行时相应值为空。操作输入限于白名单公开或合成任务。

要定位一项分数，先看 score.json 中的失败判据，再查看 observations.json 的研究请求、审核回执、方法配置、审核错误与答复证据，并使用 run_id 回到运行文件。报告哈希校验只能确认导出内容未变；数值正确性另由独立参考值核对。不得将本轮自动化任务正确率转换成真实模型准确率或真人完成率。
