# CausalOps V2.1 修复与验收

被测应用来自 `01ac605`，分支 `fix/causalops-v2-1`。基线为 `edd6719` 保存的 V2.0 Pilot，其产品源码为 `5f257e8`。本轮没有更换估计器，没有把识别假设改成默认通过。日期窗口的改动只在已登记的日期列上筛选行，描述统计与 OLS 仍使用既有实现。

## 失败如何发生

| 环节 | 旧行为 | 本轮处理 |
|---|---|---|
| 两组比例 | 已保存两组概率和差值；末答渲染时只有“处理/对照”，组名没有传入 | 登记组别名称；按所选运行追溯字典、概率、百分点差和期间。旧的公共教学库仅在原始数据指纹及分组编码完全匹配已核验的公开样本时恢复组名。 |
| 相关系数 | 报告从统计产物读取系数；自由回答取经过排序的有限事实，并可在没有采用系数的情况下返回解释或回退提示 | 明确的系数请求从同一运行的变量对读取 Pearson/Spearman 与成对样本量。变量对不能唯一确定时提示核对；有数值时交付系数、方向、来源和因果边界。 |
| 与阈值比较 | 事实目录有均值，模型可能只列事实、不给方向。有些追问省略了上一句的统计量名称 | 对能定位到同一运行、统计量与阈值的请求用 Decimal 判定高、低或相等，并给绝对差。已知概率尺度可与百分数统一后比较。不确定的单位不换算。 |
| 更换指标 | 原批准绑定计划与数据，但描述统计可以增加其他数字列；即使重点列已变，原字典仍可能沿用 | 在请求上保存本次指标、单位、日期范围及来源，形成待审新版本。历史报告仍沿自己的运行、计划和原字典解析。新版审批凭据另含本次口径摘要，实际派发再次核对。 |
| 缩短窗口 | 全期描述报告不能回答七日问题。仅把“七日”写在计划文字中也不改变计算样本 | 核对日期可解析、边界和逐日覆盖，将日期列、含首尾的起止日期写进待审配置。执行前校验同一范围并筛选数据，缺日或条件不足时澄清。 |
| 混合请求 | 路由可将多方法截成第一项，方法发现与本地计划生成也可能仅保留主要方法 | 对明确有顺序且已支持的“分布与 OLS”组合保留先后顺序，按登记的因变量与预测变量生成两个步骤。审核后产生两个运行。纯咨询不应触发计算。 |
| 新报告交付 | 新统计已经保存，界面仍可能处于后台工作阶段等候解释，此时显示的是上一报告 | 审核和等待区标注新指标、窗口及当前状态。范围明确的新版描述结果从新运行直接生成首次解释，含均值、样本量、窗口、版本和运行编号。 |

## 代码位置

- `src/causalops/application/saved_answers.py`、`report_scope.py`、`task_conclusions.py` 与 `assistant/service.py` 负责选定运行、范围核对、事实选择、答案与引用。确定性通路只在目标足够明确时接管；已有开放式解释和有界校验继续使用。
- `application/plan_scope.py`、`data_contracts.py`、`research_service.py`、`task_readiness.py` 与 `orchestration/research_graph.py` 负责请求作用域、候选审阅、批准、运行前二次检查与多步顺序。
- `general/exploration.py` 负责描述统计的真实日期筛选；`sample_data/hillstrom.py`、`ui/contracts_editor.py`、`ui/graph_app.py` 提供组名登记、待审指标说明和历史展示提示。
- 新增 `tests/test_v21_answer_delivery.py` 和 `tests/test_v21_flow_boundaries.py`。另有可重复运行的 `scripts/verify_v21_revision_flow.py`，以测试操作者身份对隔离合成数据执行显式审批，检查五条实际运行。

## 验证方法

用本项目 Python 3.11 环境，并将 PYTHONPATH 设为本次分支的 src。以下命令的输出目录须为新目录。

```powershell
& $py -m pytest -o addopts= -q tests/test_v21_answer_delivery.py tests/test_v21_flow_boundaries.py
& $py -m pytest -o addopts= -q --tb=short --basetemp=./artifacts/co-v21-new-regression
& $py scripts/verify_v21_revision_flow.py ./artifacts/v21-new-walkthrough
```

V2.0 的六题、18 次模拟的输入与计分程序保持冻结。独立控制器使用提交快照及冻结初始研究库。RC 采用单工浏览器；之前中间候选并行运行时出现过进程初始化内存错误。每批保存独立证据，补测不替换正式分母。另一独立会话保管八个新场景，首次与复测、服务调用与浏览器操作分别记录。没有真人试用数据。

| 冻结指标 | V2.0 固定 | V2.1 固定 | V2.0 适应式 | V2.1 适应式 |

| 页面信息完整 | 4/6 | 5/6 | 10/18 | 15/18 |

RC 正式24槽全部自然获得终态，128组浏览器证据完整。16次官方调用均有成功回执，来自5个固定槽；18次适应式没有调用模型。原完成指标要求官方回执且操作者符合终止条件。保留原分。15次适应式试次自行判定完成，3次放弃；模拟器判断也不能替代独立评分。

* B01、B02 的固定路径和适应式正文均已分别给出两组访问率（10.62%、18.28%）、7.66个百分点、两周及来源，或 Pearson 系数0.7202、正方向、成对样本128与非因果边界。
* B03 说明按日访客数加权，保留有访客但没有订单的日子；缺失与分母为零分别处理。
* B04 四轮均给出所选旧报告中的日均订单数8.906，低于9，差0.094。正文的单位“单”未命中固定量规所要求的复合写法，仍可改进“每天平均”的文字。
* B05、B06 在适应式各三轮中都核准新计划，每槽新增1个对应运行。六个原轮末屏均已展示新结果。B05为48条、均值76.5833人；B06为2024-02-11至02-17共7条、均值9.71429单。旧报告保留，未发现旧批准挪用。B05单位“人”未命中冻结词表，B06模拟器在报告已显示后继续等待并放弃。两题的固定路径仍未走完变更流程，不能把成功路径推广至所有表达。

### 陌生任务与限制

独立评测会话封存8个不同业务场景。第一个候选真实浏览器严格复核2/8，第二个候选1/8，后者有2个槽未到首屏。RC最后在同一冻结场景作本地生产服务重测：末次答复严格完整3/8，过程中曾交付完整结果4/8。它不是RC的8次新浏览器测试。业务标签、负相关方向与来源、无批准不能派发均有独立证据。仍有两种负数/相等阈值的自然语言问法只返回均值；缺日时能指出只覆盖4/5天，没列出缺哪天；新指标算对并即时交付，但下一轮“刚才结果”追问仍会失焦。“解释已有相关结果，同时为另一方法拟新计划”的混合意图也未完整完成。不能宣称支持任意研究请求。
