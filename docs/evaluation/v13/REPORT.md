## 修复了哪些问题

1. 原服务能够验证字段存在、方案可运行、版本获批，但没有把用户所指的业务事件和计划中的日期含义放入同一项执行前检查。因此，“用开业日估计促销效果”能够退到描述性统计并获批。新增 Measurement 记录处理事件、日期口径、分子、分母、聚合方式、分配单位与聚类标识，同既有分析单位、指标、时间窗、研究目标和数据字典共同绑定。路由、计划就绪检查和批准回执执行检查复用同一语义检查。信息不足时回答具体缺项；单独的描述研究可以保留简单合同。
2. 用户明确撤回旧候选并替换方案时，服务核对会话与候选状态，留下撤回记录。历史报告答复核对所选运行及其证据。仅咨询、不计算和涉及合并比率或整群分配的请求得到区分。统计估计器、人工审批及数据外发许可继续通过原服务运行。
3. 真实请求按逻辑调用和物理尝试分别记账。临时传输错误有限次重试，结构错误通过独立的重新生成处理。请求指纹和调用标识允许核查延迟及重复请求，但不能证明服务商对重复请求实行账单去重。
4. 这些规则只覆盖已声明的指标、时点和可识别的请求。任意同义业务词、所有跨层级指标及所有等价研究设计尚不能自动判定。没有注册执行器的汇总方式可能仍需澄清或另行分析。

## 失败、恢复和使用限制

- 原挑战开业日期案例，本地三次偏题运行降为零。新批两种模式各有 9 次新增统计运行，复核中均与请求对齐。未发生运行的任务有些只是澄清，不能视为全部完成。
- 原题 C02 中模型有两次将按访客分母合并的购买率解释为按订单量加权。C08 有一次把 8.906 说成大于 9 并误判偏态；C09 三次计算了相关分析却未向用户交付相关系数。冻结分与正文可用性有明显差距。
- C12 有一次正确引用所选报告中位数，却未命中冻结规则规定的均值；C03 有一次引用校验失败。保留原判与内容复核分歧。
- 陌生集在本地 1 次、模型 3 次子进程中止。部分结束时间与 Windows 资源耗尽记录重合，不能据此断言每次中止的唯一原因。所有中止均留在正式分母中。五次修订已切换主要指标但仍在附带体检中保留旧字段，未通过冻结判据。
- 真实正式批次 217 个逻辑调用、217 个物理请求，全部有回执。首次传输或 HTTP 失败 0/217；214/217 首次符合结构，3 次结构失败后的下一次应用层重新生成均通过。没有真实传输重试样本，因此真实网络自动恢复率未测得。模拟断线单独记账。
- 正式输入 557,684 token、输出 53,899 token。正式估价 ¥0.226750–0.773280，另有两次探测约 ¥0.002502–0.003002。区间反映缓存命中未知。以官方账单为准。首轮旧挑战冒烟有 HTTP 200 和用量回执，但未同时获得有效结构，所以该批正式槽未启动；随后独立正式批完成 45 槽。两批均保存。
- 全量回归初跑 667 通过、1 失败、1 设置错误。一个混合请求被过早缩减为分布统计，另一次建立临时 SQLite 工作区出现磁盘 I/O 错误。前者依据已有回归修复，后者更换隔离测试目录后复测。最后 669 项通过，耗时 276.91 秒。两项原失败与 3 项语义测试单独复测 5/5。固定集 10/10，含 2 个正确阻断。正式 180 个挑战槽位测的是上述冻结提交；混合请求末次修正仅做工程回归，未将此前测量归为该补丁的模型成绩。
