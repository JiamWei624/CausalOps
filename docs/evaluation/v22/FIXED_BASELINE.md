## 问题与验证边界

1. **优先关注历史指标切换。** N05 的等待条件只等任意“运行编号”出现，上一条报告本来就满足；DOM 文本与截图也非原子捕获。脚本若在此停止，会将错误内容算作成功。截图证明用户确实可能看到不配套的运行号与摘要。建议下一阶段监测“任务名、报告号、指标和摘要均匹配”到稳定显示的时间，并同时保存首次不一致画面和稳定画面。不改写本轮结果。
2. **错误文件提示和概况入口沿用第一期问题。** N08 在拒绝文件后仍提示“选择文件后显示……”，遗漏“替换文件”的具体下一步；N02 同时提供查看质量、推荐问题、已有概况和生成报告等入口。有固定路线时可以完成，不足以判断初次使用者会选哪一个。
3. **操作次数依赖实现。** N05 的选择框打开与选项选择分别计数；N06、N07 各有一次展开选项的按键。统计提交后的等待、Streamlit 重绘、截图时间和用户阅读时间不能混作同一指标。没有超时或最终失败，仍保留 N05 的不一致和 N08 的注入错误。页面错误事件为空不等于没有语义错误。
4. **独立性边界。** 后置脚本使用只读 SQLite，核对产物、审批、数据指纹、方案版本、会话和真实页面。N05 的两份营销报告位于两个有意义的任务名之下，本题不能替代同一会话中多个同名报告的测试。新旧报告的正文与编号比较只覆盖本次旅程。浏览器程序本身不是独立真人，后置核查也不能证明持久存储所有历史字节从未被修改。

## 复现、证据与后续建议
