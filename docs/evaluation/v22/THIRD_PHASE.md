## 报告切换

原 N05 首张历史页面截图中，编号对应访问率，正文却仍为购买率。旧终点截图已恢复正确。render_history 先更新运行选择、编号与指纹，再构造结论、单独写出正文和证据。这些前端元素分次替换。旧脚本等待任何运行编号出现，可能在两次更新之间截屏。后端核对时两个运行各自的指标、方案及证据均正确。本案有依据的修复位置是历史页渲染和浏览器等待条件，没有发现需要修改统计内核、缓存或持久化会话的证据。

新增 history_transition.py 后先在旧代码交替选择两个报告六次。按浏览器动画帧保存选择任务、选择运行、正文指标、两周窗口、正文、来源和 performance.now 时间。修复前六次均出现编号与正文错配。按每次第一个错配采样到下一状态采样计算，依次为 80.6、110.1、120.2、81.4、84.1、83.1 毫秒。这是本机采样间隔，包含帧分辨率，不是服务端耗时。早期探针第一次试验未正确读取下拉框值，保留在 before；时间和选择状态采用已校正探针的 before2。

workbench.render_history 现在先取齐该次运行，再由 history_report.history_html 将任务名、方案版本、指标、窗口、运行编号、指纹、幅度和证据放进同一个 HTML 区块。插入的文本经过 HTML 转义，方法链接只保留 HTTP(S)。运行选择响应过程中可以暂时保留先前报告；标题“所示报告”明确标注此刻展示的来源。fixed_remaining.py 等待目标任务、运行、指标、窗口与正文同时出现。专项测试还要求运行和正文持续一致至少 250 毫秒。

修复后同样六次切换，采到 19 个不同状态，编号与正文错配 0 个，无来源说明的旧报告 0 个。自由探索三次 N05 的已保存帧也没有采到错配。动画帧采样不能证明每种浏览器、网络环境都绝无瞬时偏差。原始历史证据未被覆盖。

## 自由探索

每次采用新的工作区、服务和浏览器上下文。模型仅接收公开或合成题面、当前页面可见文本、控件列表和自身近期决定。脚本将模型选择派发到真实浏览器。模型没有读取代码、数据库、评分器或正确路线的工具。官方模型每步产生一个决策；控制器不接管失败操作、不自动重试输出结构错误。独立评分在会话关闭后读取截图对应文本、动作、初始基准、只读数据库和保存的统计证据。N05 以访问率的实际运行标识核对，任何购买率结果均不得替代。N06 要求真实的新批准与新运行。N08 要求刷新后仍能在原会话看到两行。
