# 处理后调整与重复实体说明 · 修复验收

## 证据与根因

T04 在旧版审计中已有 `timing:post = block`。待审 OLS 的实际字段配置包含 `predictors=[group, post]`。当研究目的为因果时，原方案校验与审批事实提取只检查 covariates；只有预测任务才把 predictors 纳入时序检查。因而合法字段名、数值类型和完整版本回执可以同时成立，仍留下错误的调整设定。旧版产生 1 份批准、1 个 OLS 运行，结论等级为条件关联。

T03 在旧版已有 `repeated_entity = review` 和 60 条超出首条的重复观测。研究图谱的 data_profile 节点重新调用通用 overview，答复仅列行列数和缺失信息，未引用先前保存的 research_quality 审计。用户无法从该答复区分 120 行与 60 个用户。

## 实施范围

| 文件（src/causalops 下） | 修改 |
|---|---|
| application/variable_timing.py | 集中判定时点、处理与调整角色。对已登记因果目标的回归，将实际 predictors 中除处理变量以外的字段作为调整输入。因果调整的已知处理后或未来变量阻断，未知时点要求先完善字典。 |
| application/task_readiness.py、application/data_contracts.py | 生成候选的就绪检查及人工批准复用同一规则。研究者确认框无法改变登记时点。 |
| application/research_service.py、assistant/service.py | 已批准的工作流在执行/恢复时重核绑定版本与时序；直接调用低层执行服务时也检查领域回执及声明一致性。已登记字典的会话不能利用未绑定的旧计划启动计算。 |
| application/research_quality.py | 根据登记的实体字段计算非缺失不同实体数、重复实体数、超出首条的重复观测及缺失标识数。实体—时间键检查独立保留。 |
| orchestration/research_graph.py | 数据概况答复读取该流程的已保存审计。重复观测出现时给出按分析单位核对聚合、面板或聚类的操作说明。 |

合法描述或相关分析仍可计算；回顾性 OLS 也能使用事后测量的解释变量作条件关联。处理变量本身出现在因果回归的预测列时不能当作控制项误拦。测量时点是研究声明，处理前或时间不变标签不能单独证明识别成立。当前规则没有实现中介分析或受控直接效应；没有根据估计对象的自由文本给处理后调整开例外。不同实体数是按登记标识的去重计数，不表示统计独立。无标识的行不被当作同一个实体。
