## 证据边界与修复顺序

- 24槽均从预绑定研究任务链接起步。独立追加的一次真实浏览器核查从无任务参数的首页按研究名称打开历史订单报告，在实际刷新前后比较了报告、方案版本、完整运行编号、对话、报告全文和当前答复，六项一致。单任务库可恢复不能证明在几十项研究中容易找到正确报告，也不能证明网络断开后能恢复。
- 100组正式页面观测各保存截图、可见文本、JSON。屏幕全页截图包含需要滚动的区域；没有逐像素核验所有视口。模拟器有时在后台仍工作时按预算退出，这是用户行为策略与页面反馈的交互，不能泛化为真人放弃率。模拟器知道目标研究标题，采用确定性策略，重复三次未增加参与者人数。模拟器与评分器按代码与数据流隔离，没有使用操作系统级对抗沙箱。
- **优先级一：指标与版本一致性。** B05应在审批时同时校验目标指标、计划和数据字典版本；执行开始后明示“显示的仍是上一份报告”，完成后自动选中新运行。验收时分别核对新旧批准、运行与页面正文。
- **优先级一：将所求事实交付在末答。** 按所选运行提取指标、单位、比较对象、期间及来源。若事实已存在，直接显示值及其比较方向；可由确定性规则生成阈值关系。B02要求末答给出系数，B04要求末答给出低于/等于/高于，B01要求具体业务组名称。
- **优先级二：口径咨询与历史窗口。** B03优先读取已经登记的分子和分母，区分购买人数和订单量的适用口径，再决定是否需要澄清。B06先检查已有时间覆盖，再提供受审窗口变更；明确“未核对”和“数据不可得”。
- **评测器与浏览器。** 下一版冻结前修正概率等义表达、旧值与新值的错误比较，区分用户提问与结论正文。给模拟器增加对在途计算的可见等待，并从混合任务列表选择报告。保留本次分数作为基线，另做并列评分。真实人群完成率和工作效率尚未测量。
