## 未通过判据的原因

**T04 · 优先修复执行门禁。** 任务的研究目的是因果调整，输入明确标记 post 在处理后测量。数据审计产生 timing:post = block；OLS 候选却把 post 放入 predictors，配置就绪标志仍为真。测试操作者按标准流程批准后，内核执行了含 post 的 OLS。运行保存为条件关联，未发现绕开版本审批；但按任务的识别条件，这一步应先拒绝错误调整或要求重新设计。建议把处理后字段的角色检查贯穿研究目的、候选配置和执行门禁，同时保留纯描述或只讨论方法的合法路径。回归时至少对照处理前变量、处理后变量、未知时点三种输入。

**T03 · 优先修复用户可见解释。** 合成数据有 120 行、60 位用户。结构审计发现 60 条重复实体记录并标记为待核对，但概况答复仅说明行列数、缺失及每行含义未知。评分分别检查了后台审计和用户答复，后一项未达标。建议在问题涉及用户编号或行粒度时，引用已保存的 repeated_entity 诊断，说明重复次数与观测依赖，同时保留原始记录。

**可复核的恢复样例。** T08 的第一份方案已获测试操作者明确批准但未派发；更换结果字段后，对旧流程的执行尝试被拒绝。再次审批后仅新计划产生运行。T10 的模拟客户端确实被调用并报错，操作者明确切到本地后得到带方法引用的回答。这验证受控故障处理，不能据此推断真实服务商的可用率。
