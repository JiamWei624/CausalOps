# 用户行为与观察记录规则

准备脚本在仓库外生成只有表头的`participants.csv`、`attempts.csv`、`interactions.csv`、`issues.csv`和空的`human-results.json`。它们没有伪造参与者或尝试，尚未招募时`participants=[]`、`attempts=[]`、完成率为`null`。实际记录不提交Git；只归档经授权的脱敏汇总。

## 必填身份与状态

每行使用匿名参与者码、`actor_type`、任务、尝试号、模板/模型模式、同意状态、产品提交、任务/报告引用。`actor_type`严格分为`human_participant`、`owner_preview`、`fixed_script`；不能通过`local_user`事件推断。开发者重复操作不增加独立参与者分母。

`participants.csv`仅填匿名编码、同意记录引用、分析经验档位、数据/产品熟悉度、任务次序和允许的记录范围；不填姓名、单位或联系方式。尚未招募时保留零行数据。

`completion`为`independent_complete / assisted_complete / partial / not_completed`；`understanding`为`correct / partial / incorrect / not_measured`。功能终点、报告来源、理解和独立性分别填写。未执行任务标明原因，不填0秒或虚构失败。模拟的理解字段必须为`not_measured`。

## 计数定义

有效操作：一次有意的点击、选择、复选框切换、完整字段填写/修改、文件选择提交、导航、刷新或下载。文字按一次完整编辑计，不能逐键累计；下拉展开并选择一项算一次选择。阅读和滚动不计有效操作，可另记导航。提交后的技术等待、页面自动重绘和后台步骤不计用户操作。

重复/无效操作另计：同一未变化状态下重复提交、点不可用目标、误选后撤销等。错误选择、回退、帮助和外部介入可以是同一事件的不同属性，不能简单把所有指标加成总操作数。观察者不确定时标为待复核，不猜测意图。

里程碑事件`data_imported/conditions_confirmed/plan_created/review_submitted/execution_started/research_completed/report_viewed/user_restore/task_stopped`来自既有`configurable_user_events`。一次里程碑可能对应多个动作，重复呈现可能重复出现`report_viewed`；**不能据此计算全量点击**。默认采用现场逐项记录；录屏回放须单独同意。

请求帮助：参与者主动问如何继续、含义或遇到问题；主持主动提示也计帮助，区分发起人和级别。操作员介入是他人实际代操作或维护环境，不能记为参与者有效操作。脚本没有真实求助动机，其帮助数填`not_measured`，控制器介入另记，不能称自主用户未求助。

总耗时从任务读完且明确开始到提交完成复述/放弃/超时，包括等候；实际研究执行时间按后台步骤起止另列，无法分离则空缺。C从B报告起计，前置准备不能算作C用户自己完成，也不能把C耗时宣传为从零研究时长。

错误类别：字段/单位/记录粒度、设计条件、计划/审批理解、导航/历史查找、报告/证据理解、恢复、产品执行、网络、模型结构、模型建议、脚本选择器/派发、外部介入。每项需页面/时间/任务引用；不只凭关键词判断根因。

## 记录字段

`attempts.csv`保存起止时间、总秒数、有效/无效操作、帮助、介入、误配、回退、错误类别、恢复、是否找到报告、理解、完成类别和引用。`interactions.csv`按序保存动作标签与时长，不默认保存输入值、文件名或原始行。`issues.csv`保存观察来源、影响、优先级、实际出现次数、证据和处理状态；审计假设标为待真人核查，不写成高频真实问题。

用户自由反馈只记经确认的必要脱敏摘要。模型请求数/令牌来自实际持久账本；用量未知和未定价分别记录。无真实模型请求时不填0元成本，无真人时不输出真人成功率。

## 质量核查

汇总前核对同意、实际执行身份、任务起点、版本、数据哈希、任务/计划/Run及报告一致性。首次失败不删除，重试独立编号；同一参与者复跑不视为新增独立用户。开放式理解由主持按完整回答复核，保留争议，不以关键词自动判理解通过。
