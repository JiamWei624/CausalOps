# Hillstrom首版规则清单 · 设计版1

以下14项是拟实现/适配规则，不是本轮已执行诊断。规则包`hillstrom-diagnostics-v1`尚未投入产品。阈值优先沿用原工具，新增对照只能规范化既有结果，不能重估参数。状态语义见[合同](CONTRACTS.md)。

## 历史与当前执行许可

PD-01分别核对原保存证据的归属/完整性与当前是否允许继续执行。代码版本变动导致的旧批准失效，不等于历史Run被损坏：历史已完成记录可按原版本只读验证，并标明historical_read_only；不得重新签发批准。若数据/工件本身hash错误，才按相应完整性问题停止引用。当前执行仍完全服从原_verify/_binding。

## 执行顺序和去重

先验证上下文/所有权，再决定是否为preflight与哪些步骤实际完成；身份或内容失败后，不继续从不可信正文运行其他数值规则。下游输出尚未检查，并关联同一个根因，不将一个受损Run重复渲染为十余项独立统计问题。合法preflight的空Plan/Run不是完整性失败。

B预诊断只读合同/来源记录：可检查PD-01引用、PD-02来源、PD-06声明窗口与PD-13范围；没有S01/统计产物的其他检查不现场补算。它不把字段齐全称为两组实际样本检查通过。

来源URL存在不等于可信或已查阅。只有登记过的来源范围和实际人确认记录才能支持相应来源检查；模型评价、相同组名或均衡都不能替代。历史来源声明与新版逐项审阅记录分别标明，不编造旧任务的审阅人、时间或段落。

## 适用性与保守映射

- 预诊断B没有Run：PD-02可检查“来源记录缺失”；统计结果、区间和双Run检查为尚未检查，不能伪造Run。对无需因果对照的纯分布任务，A/B专属条件可不适用，不能一律报因果风险。
- 旧DiagnosticResult.passed=False可能表示“未检查”，不是必然已发现问题；research_audit.review可能是需人核对的合法编码或重复测量，不直接升级为critical。
- 当前无协变量保护确实存在。本设计不把函数前半段的max_smd默认值当成最终诊断；对未来不认识的旧诊断名保留原文并标unknown/需人工复核，不能靠关键词补出通过。
- 不把0.10当普适识别边界；不新增SRM检验、功效分析或PSM/DID专属自动诊断。组规模不同本身不是本版随机化失效证据。
- 若执行模块没有产物，明确尚未检查；若规则尝试检查必要记录但记录缺失，标未知；若该方法/目的不需要条件，标不适用。输出数量由适用规则决定，不凑风险或建议数。

## 建议目录与触发

|行动类型|触发与理由|数据/计划/审核要求|
|---|---|---|
|查看保存依据|已存在有效Run或研究来源，需要用户复核|只读，不改计划、不审核执行|
|补充设计来源|PD-02未知，解释因果主张缺的依据|需要公开设计说明/人工核对；正式合同变化后旧批准失效，不能仅通过诊断备注恢复统计|
|核对报告选择范围|PD-01/06/07冲突|先选择同任务/同范围合法Run；没有匹配数据时说明不能计算，不自动用旧结果|
|登记后续研究需求|有具体未检查条件或用户明确新增目标，且有相应依据|说明缺数据、方法支持性及新审批要求；首版只生成需求草案，不绕过固定Plan限制|
|暂不处理|用户明确决定延期|追加事件，状态和必要结论限制保留|

可选模型只能在这些动作类型中选择，最多3项；若没有相关问题，返回空数组。不得以“使p<0.05”为建议目的。

### 状态与影响的默认政策

以上每个分支必须在规则注册表中形成完整的状态、严重度、结论影响和原因码，表格省略处不能由模型补写。默认政策为：verified、not_applicable、not_checked使用information；unknown中若影响当前目标所必需的事实，则major，否则information；issue按该行列明的critical/major/moderate执行。unknown不能因为证据缺失直接宣称研究事实为假。

运行缺失、区间缺失、样本不匹配等问题只有在适用前提与可验证来源确定后才判定；身份或工件失败优先由PD-01记录，下游不读取受损内容，并标not_checked。impact采用明确的受影响主张集合并按更严格限制合并，不通过严重度平均、模型投票或用户暂缓解除。
