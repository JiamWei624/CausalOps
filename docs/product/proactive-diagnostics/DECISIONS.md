# 负责人需要确认的设计取舍

产品方向和本轮只设计边界已经明确，不重复询问。以下是本方案的具体建议，**尚不是负责人正式批准的工程实现**。

|取舍|推荐|代价/替代|
|---|---|---|
|首版是否依赖模型|默认规则+确定性模板即可交付；第3阶段可选受限模型解释，单独授权与预算|表达可能较朴素，但不借旧0调用批准外发；若首版必须模型，需要先完成新只读Grant/预算能力|
|如何表示证据质量|五态+来源+明确结论限制，不生成总分|无法用单一分数排序；换取不会把未检查、人工声明混成“高可信”|
|设计依据不足怎样接入|已有原生数据合同的只读预诊断；不改变固定Hillstrom准入|不能用任意上传表体验完整固定链；避免假称未知实验已随机化或伪造AB|
|采纳建议是否生成计划|先登记证据请求或研究需求草案；支持性确认后由用户明确请求新待审方案|多一个确认边界；避免将“采纳建议”误解为“批准并执行”|
|基线平衡与方法扩展|首版只解释保存诊断，不为补全报告新算SMD或增加其他方法|不能即时回答所有设计问题；后续按独立研究需求评审，不自动换CUPED/PSM/DID|

建议一次审阅确认前三项核心交互与模型取舍即可，后两项按本轮技术范围执行。暂不要求全部开放研究问题通过，也不以历史题集成绩提高作为上线标准。

## 实施前仍需明确

- 若开放模型解释：使用哪一已配置服务、授权的聚合字段范围与只读预算实施方案；本PRD不提供API密钥或价格事实。
- 原型中的词语、来源分组和行动草案流程是否接受；原型未实现，不能据此承诺用户提效。
- 首版上线时是否仅启用固定任务完成后的主动评估，并将原生合同预诊断作为明确的次入口；推荐保持两个入口清晰分离。

所有未来计划/方法/窗口变化继续重新审核；这些问题不允许以普通勾选覆盖已确认事实冲突。
