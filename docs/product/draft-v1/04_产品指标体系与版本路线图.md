# 产品指标体系与版本路线图
**V1.0 候选｜待最终确认｜依据归档 1737c9c**
指标用于分别检验价值、交互、研究质量和执行安全。没有独立真人数据时，真人指标标“未测”，不能用模拟数据填入。引用见[证据索引](00_材料核查与证据索引.md)。

## 1. 指标分层
| 层次 | 指标 | 分子/分母或计算方法 | 失败及适用边界 |
|---|---|---|---|
| 用户价值（未来真人验证） | 有效任务独立完成率 | 无逐步开发者指导且达到预定有效终点的人次 / 全部开始的有效人次 | 失败/中断留在记录；访谈筛除规则需预注册，不能事后剔除困难者 |
| 用户价值 | 结论理解正确率 | 能正确解释目标、单位及限制的人次 / 被问及的有效人次 | 不能仅问“看懂了吗”；当前未测 |
| 用户价值 | 首份有效报告耗时 | 从规定起点到有效报告的实际时间 | 同时报告失败/超时；不能只报告成功者均值或将不同起点混合 |
| 交互 | 固定流程完成率 | 达到冻结终点次数 / 全部固定尝试 | 测可用路径，不测自由可发现性 |
| 交互 | 自由探索完成率 | 无隐藏路径帮助、达到全部终点次数 / 全部独立尝试 | 包含失败、超时、模型动作中断；分原因 |
| 交互 | 正确停止率 | 完成后正确停止的次数 / 全部尝试；另列条件停止率 | 模拟器提前/延迟结束与产品未完成分开 |
| 交互 | 有效/无效/重复操作 | 控制器真实 click/select/fill/send/upload/refresh 事件 | 等待和截图不算操作；重复可能属于有效操作，不把它们强行相加 |
| 交互 | 求助与外部介入 | 主动请求帮助事件；外部操作员纠偏事件，分别计数 | 0 次不是“无需帮助”的真人结论 |
| 恢复 | 故障恢复率 | 注入/实际故障后达到恢复终点次数 / 有恢复机会的故障次数 | 无故障为不适用；预置修正文件标受控恢复 |
| Agent 研究质量 | 正确处理率 | 完整 + 正确阻断 / 实际执行研究任务 | 部分/失败/争议不计成功；未执行另报覆盖，不伪装已执行失败 |
| Agent 研究质量 | 计划约束一致性 | 目标、字段、窗口、样本等必要约束均落实的计划 / 适用计划 | 文案提到不等于实际配置支持 |
| Agent 研究质量 | 答复充分性 | 满足本题全部必需回答要点 / 适用尝试 | 数值对但解释漏，不能完整；开放语义保留复核 |
| Agent 研究质量 | 数值与来源匹配 | 数值、单位、指标、窗口、Run 均一致的核对项 / 适用核对项 | 不跨 Run 拼接；确定性答案无需人为强制调用模型 |
| 执行安全 | 未批准执行数 | 无有效绑定批准却产生新统计运行的实际次数 | 任何一次须单列严重风险；“未观察到”不等于全场景不可能 |
| 执行安全 | 历史保持 | 变更前后历史记录/证据指纹一致的检查 / 适用检查 | 只读问答、修改与实际执行分别核对 |
| 模型接口 | HTTP/结构化有效率 | 分别为成功响应/物理请求、有效结构输出/请求 | 重试每次计入；HTTP 成功不等于内容正确 |
| 运行成本 | 延迟、token、费用 | 实际计时、服务回执；按对应价表估算费用 | 无用量不猜测；估算不冒充账单，模拟器与被测产品调用分开 |
| 工程质量 | 测试通过/失败/跳过 | 该代码版本下的实际测试数 | 不作为 Agent 正确率，不把局部测试与完整套件相加 |

**推荐的主价值指标（待批准）：**限定主场景下“独立完成有效研究任务且正确理解结论”的比例。当前只有自动化材料，不能为它填历史值。目标值需在真人试用协议中另定，不在本稿凭空指定 90% 或提效 50%。

## 4. 持续质量待办与下一代需求优先级
当前 Beta 的定位为**可审核、可追溯的 AI 数据科学 Agent**；下一代为**受控自动化的数据科学 Agent**；长期为**自动化数据分析与研究工作台**。后两者为规划，未排期或开发。

### 4.1 持续质量与体验待办
以下来自已有证据，保留风险，不另设与下一代路线竞争的优先级：
- 指标、分母范围、研究条件和最终解释的一致性：错误方案即使未执行，建议仍可能误导。严重问题按实际影响处理。
- 答案交付完整性：已有数值并不代表回答了用户全部问题；缺证据时不得补造。
- 导航和状态可理解性：N06 三次探索未达到完整终点，不能因固定路径成功就宣称体验达标。
- 真人验证：尚无真人任务完成率或效率数据，后续研究需定义任务、帮助、失败和理解检查。

### 4.2 负责人已认可的下一代优先级
| 优先级 | 需求方向 | 边界与理由 | 未来验收方向（未实测） |
|---|---|---|---|
| 持续 P0 | 研究正确性、证据约束、审批与执行安全 | 所有版本的持续底线；不要求所有开放问题全通过后才开发新功能 | 目标、指标、配置、批准与证据一致；越权、证据混用和无依据结论单列 |
| P1 | 有界多步骤自主规划 | 首版建议单表、明确目标、已有方法；当前有限步骤不等于完整自动规划 | 有效计划、依赖满足、执行一致、正确停止及可追溯结果整合 |
| P1 后续 | 基于证据的主动诊断 | 建立在步骤证据与受控计划上；不擅自改设计事实 | 有依据地识别问题，提出可审核候选，保留失败与旧运行 |
| P2 | 多表数据与指标管理 | 单独处理连接基数、实体粒度、窗口与血缘 | 不做隐式连接或分母替代；不预连接数据伪装产品完成 |
| P2 | RAG 专项评测与必要优化 | 先测检索与引文质量，再决定必要改动 | 覆盖、依据准确、拒答与版本分别检查 |
| P3 | 定时任务、外部工作流和多人协作 | 长期持续工作流；当前本地单用户结构不等于云平台 | 显式授权、触发与停止、数据隔离、身份和权限分别验收 |

这是已认可的方向顺序，**不是排期、开发授权或已完成成果**。P0 要求拟支持范围内可解释地执行、澄清或阻断，不把穷尽所有未知研究问题作为功能发展的前置条件；也不能据此容忍拟支持范围内的真实高风险执行错误。

**已完成：**公开 Beta基础链路；V2.2 导航/状态和模拟器迭代；V2.3 50题建设、30题开发、13/20保留实际首次评测与归档。V2.3已结项，不再要求所有题通过。

**当前：**V1.0 产品文档候选待最终确认；用户顺序、营销演示、三阶段定位及上述优先级已明确。具体画像痛点与收益仍未真人验证，不重跑50题。

**下一步建议：**另获授权后编写[《多步骤自主研究规划专项 PRD》](06_自动化方向需求概要.md#special-prd)，先界定单表、目标明确、既有工具、审批及步骤/费用/失败停止范围。负责人确认专项 PRD 后才能实施，不以本候选文件替代开发授权。

**后续顺序：**有界规划 P1 → 基于证据的主动诊断 P1 后续；多表数据与指标管理、RAG 专项评测与必要优化均为 P2；定时任务、外部工作流和多人协作为 P3。具体资源、日期及相同优先级内部排程未确定。真人验证与持续质量工作依场景安排，不虚构已排期试用。

## 7. 数据与评分治理
保留原问题、输入、输出、候选、Run、时间、原评分、复核意见和版本。工程测试、模型建议、安全门禁、最终回答、浏览器动作及真人理解分别记录。指标新增或规则变化必须留版本，不能覆盖冻结成绩。运行数据和隐私材料不因制作作品集自动公开。

## 8. 未来自动化指标定义（全部未实测）
以下指标是下一代专项 PRD 的定义候选，不回填历史值、不设未经确认的目标百分比。每次尝试先冻结任务边界、允许步骤、批准范围、预算和停止条件；模型重试与计划修订保留全部版本。安全门禁纠错不计作模型原计划有效。

| 指标 | 定义与分母 | 失败、范围与配套记录 | 当前值 |
|---|---|---|---|
| 计划有效率 | 首份候选同时符合目标、必要条件、工具能力、依赖与预算的任务数 / 全部已启动规划任务数 | 无输出、超时、结构或语义错误留在分母；另报允许修订后的有效率，不覆盖首份结果；解释争议独立复核 | 未实测 |
| 步骤执行一致性 | 实际配置、输入、顺序、批准版本和输出来源均符合计划的步骤尝试数 / 全部已发起步骤尝试数 | 非法或配置错误尝试计不一致；工具故障与任务完成另计。未发起的必需步骤另报覆盖，避免只执行一小步却显示全面成功 | 未实测 |
| 任务自主推进率 | 未经计划外人工代操作而完成全部约定可自动化步骤的任务数 / 全部进入自动执行阶段的任务数 | 正常人工审核不等于失败，也不被省略；失败、超时及非预期接管保留。另报从全部任务起点到最终有效交付的完成率 | 未实测 |
| 正确停止率 | 在预定完成、预算/失败边界或安全条件出现时正确停止并说明的次数 / 实际出现这些停止机会的次数 | 提前误停、应停未停、理由错误单列；无机会为不适用，不填100%；成功完成与异常停止分别报告 | 未实测 |
| 人工接管率 | 自动执行中实际请求人工接管的任务数 / 全部进入自动执行阶段的任务数 | 这不是越低越好的指标；计划内审批、必要接管、无必要接管分别记录，不能用低接管率鼓励越权 | 未实测 |
| 正确人工接管率 | 正确提出具体接管请求且保留状态/证据的机会数 / 根据冻结条件必须接管的机会数 | 漏接管、迟接管、泛化提示与无必要请求单列；没有真人完成接管时不能宣称人工恢复成功 | 未实测 |

计时建议：规划从用户提交明确目标至形成候选或失败；执行从有效批准后开始自动步骤至完成、停止或接管。单独记录模型等待、工具执行、人工等待及费用回执；端到端时间不能只取成功自动步骤。事件应包含任务、计划版本、步骤、批准、运行和停止原因，具体事件合同由专项 PRD 与实现设计确定。

本表不承诺新增采集代码已存在。现有评测日志可以评估复用，但需按上述分母检查适配；不将历史模拟用户指标当作下一代自主规划指标。
